# Versa — постатейное сравнение документов

Прототип для задачи Казахтелекома на HackAlem AI. Главный экран — сравнительная таблица из **трёх столбцов**:

1. **Документ 1** — полное название, номер пункта и исходный текст.
2. **Документ 2** — полное название, номер пункта и новая редакция.
3. **Что изменилось** — пояснение к каждой паре.

Все пункты отображаются по порядку документа 1, включая неизменённые. Новые пункты документа 2 включаются между соответствующими пунктами. Удалённые фрагменты выделяются красным и зачёркиванием; дополнения — красным жирным текстом с подсветкой. Ничего не нужно раскрывать, чтобы прочитать изменение. Доступны поиск и фильтр «Только изменения».

Репозиторий: [BAITC-Hacks/hack-e384891b-ainalineast-coder](https://github.com/BAITC-Hacks/hack-e384891b-ainalineast-coder).

## Запуск

Требуется Python 3.10+ и современный браузер. Проверено на Python 3.12.14/Windows. Откройте терминал в корне проекта:

```sh
python -m pip install -r requirements.txt
python -B app.py
```

Откройте **http://127.0.0.1:8765**. На Windows можно использовать `start.cmd`, если Python доступен в PATH. На Linux/macOS при необходимости замените `python` на `python3`. Остановка — Ctrl+C.

Сразу загружаются предоставленные обезличенные редакции 8 и 9. Базовый сценарий не требует интернета, API-ключа, Node.js или установки модели. Шрифт Roboto входит в проект и загружается локально.

## Форматы

Импорт MD/TXT, DOCX, XLSX, CSV/TSV и экспорт HTML, CSV, JSON, XLSX используют стандартную библиотеку Python. Для импорта PDF и экспорта Word/PDF установите зависимости:

```sh
python -m venv .venv
# Windows:
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -B app.py
# Linux/macOS:
# .venv/bin/python -m pip install -r requirements.txt
# .venv/bin/python -B app.py
```

Зависимости: `pypdf==6.10.0` для чтения PDF, `python-docx==1.2.0` для Word, `reportlab==4.4.9` для PDF. Без них базовое сравнение и HTML/CSV/JSON/XLSX доступны; экспорт Word/PDF покажет инструкцию установки. Сканы, SmartArt и схемы без текстового слоя требуют предварительного OCR. DOC/XLS преобразуйте в DOCX/XLSX. Формулы Excel не пересчитываются. Предупреждения об ошибках извлечения включаются в результаты.

## Проверка сценария для жюри

1. Запустите приложение — появится полная таблица редакций 8 и 9.
2. Введите **9.15** в поиск: сразу видны оба текста и добавленное «может», рядом — пояснение.
3. Очистите поиск. Включите «Только изменения», затем «Все пункты». Порядок пунктов сохраняется.
4. Проверьте §3.4 — изменение состава подразделений.
5. На вкладке «Документы» можно загрузить свои файлы и изменить отображаемые названия. Изменение входа сбрасывает старый результат.
6. Нажмите **«Скачать таблицу»** или **«Скачать»** над таблицей. Выберите Word (DOCX), Excel (XLSX), PDF, HTML, CSV или JSON. Экспортируются все строки независимо от текущего фильтра. Word, Excel, PDF и HTML сохраняют три столбца, названия документов, весь текст и цветовое выделение изменений.
7. Файлы сохраняются в локальную папку `exports/` и скачиваются браузером. Word/PDF используют альбомный A3; в Excel закреплена шапка, включён фильтр, длинные пункты продолжаются на следующих строках без потери текста.
8. На вкладке «Заключение» доступны дополнительные замечания по функциям, ссылки на источники и решения эксперта.

Таблица стала выше; кнопка **«На весь экран»** разворачивает её на доступное окно. Возврат — **«Свернуть»** или Esc. Полосы прокрутки контрастные синие. Отсутствующий пункт обозначается фразой **«Данный пункт в документе отсутствует.»** в обоих документах и экспортах.

CSV содержит те же три столбца, но не поддерживает цветовое оформление. JSON содержит полный структурированный анализ. HTML на вкладке «Заключение» включает таблицу, замечания, источники, рекомендации и решения эксперта. Решения в интерфейсе действуют до перезагрузки; сохраните HTML-заключение или JSON перед закрытием.

## Заключение и юридические обозначения

Названия документов отображаются без технических расширений. Полные ссылки на пункты, подпункты, разделы и статьи формируются по структуре источника; неизвестная иерархия не достраивается из номера. Ненумерованные абзацы обозначены отдельно. Исходные цитаты и перечень изменений выводятся полностью, без искусственного сокращения слов и ограничения количества изменённых фрагментов.

Заключение включает предмет сопоставления, основные выводы, замечания о распределении функций и полномочий, последовательный перечень всех изменений и дополнений с полными цитатами обеих редакций, рекомендации и пределы анализа. Изменение текста документа не объявляется нарушением законодательства без соответствующей проверки. HTML-заключение сохраняет весь этот текст, решения эксперта и полную сравнительную таблицу.

## Воспроизводимость

```sh
python -B -m unittest discover -p "tests*.py" -v
python -B verify.py
```

`verify.py` записывает в `validation/` актуальные тесты, измерения, анализ и самостоятельные отчёты. Главные результаты новой версии — `audit-comparison.html` и `control-comparison.html`. Сводка `summary.json` содержит отдельную статистику постатейного сравнения.

Тесты проверяют полный охват обеих редакций, порядок, неизменённые пункты, добавления, удаления, перенумерацию, восстановление исходного текста из выделенных фрагментов, а также прежние проверки анализа функций, загрузки форматов и экспорта. Число тестов и время текущего запуска смотрите в сохранённом протоколе; эти проверки не являются оценкой промышленной точности.

## Архитектура

- `app.py` — локальный HTTP API и интерфейс.
- `comparison.py` — полное упорядоченное сопоставление пунктов и словесные различия.
- `comparison_report.py` — самостоятельная сравнительная таблица для проверочного запуска.
- `export_api.py` — проверка запросов на экспорт и выбор формата.
- `export_documents.py` — Word/PDF с полным текстом и выделением изменений.
- `export_xlsx.py` — самостоятельный OOXML-экспорт Excel.
- legal_text.py — полные названия и ссылки на действительную структуру источника.
- legal_report.py — развёрнутое заключение по установленным различиям.
- `backend.py` — дополнительный анализ функций, ответственности, источников и необязательная Ollama.
- `index.html`, `app.js`, `styles.css`, `assets/` — интерфейс Versa.
- `data/` — предоставленные обезличенные редакции.
- `tests*.py`, `verify.py`, `validation/` — проверяемость.
- `docs/` — архитектура, сценарий защиты и соответствие критериям.

См. [архитектуру](docs/ARCHITECTURE.md), [сценарий защиты](docs/DEMO.md), [критерии](docs/CRITERIA.md), [дизайн](docs/DESIGN.md), [сторонние компоненты](THIRD_PARTY.md).

## Дополнительная локальная языковая модель

Постатейная таблица работает без модели. Для дополнительного анализа функций поддерживается заранее установленная Ollama на 127.0.0.1:11434.

```powershell
$env:ORGLENS_LLM_MODEL = "имя-установленной-модели"
python -B app.py
```

На Linux/macOS: `ORGLENS_LLM_MODEL="имя-модели" python3 -B app.py`. Затем включите соответствующий флажок в интерфейсе. Модель и Ollama не входят в поставку. При отказе используется автономный режим с предупреждением. Живая LLM в этой среде не запускалась; отказы и вымышленные ссылки проверены имитацией ответа.

Порт можно изменить через `VERSA_PORT` или совместимый `ORGLENS_PORT`; по умолчанию 8765. Имена переменных ORGLENS сохранены для обратной совместимости. Сервер слушает только 127.0.0.1; корпоративные аутентификация и многопользовательский доступ не реализованы.

## Ограничения

Пояснение описывает различия предоставленного текста, а не юридическую причину изменения. Сильное перефразирование может потребовать ручной проверки пары. Порядок документа 1 является основным: перенесённые пункты второй редакции могут отображаться рядом с прежним местом для удобства сравнения.

Исходные документы содержат ссылки на российские нормы — агент не подменяет их законодательством Казахстана. Отсутствие функции в загруженном комплекте не доказывает её фактическую утрату. Внешние нормативы и бенчмаркинг операторов не предоставлены и не заявляются.

Лимиты: 30 файлов на сторону, 15 МБ на файл, 600 000 символов на документ; дополнительный функциональный анализ ограничен 1800 пунктами. Пользовательские экспорты исключены из Git. Документы — данные; инструкции внутри них не выполняются.
