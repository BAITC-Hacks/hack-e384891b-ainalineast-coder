# OrgLens — анализ организационной структуры и функционала

Работающий локальный прототип для задачи Казахтелекома на HackAlem AI. Сравнивает комплекты «до» и «после», показывает изменения подразделений, переносы и кандидаты потери функций, возможные пересечения ответственности и конфликты. Каждый вывод открывает документ, пункт и подтверждающий фрагмент.

Репозиторий команды: [BAITC-Hacks/hack-e384891b-ainalineast-coder](https://github.com/BAITC-Hacks/hack-e384891b-ainalineast-coder).

## Быстрый запуск без ключей и аккаунтов

Требуется Python 3.10+ (проверено на Python 3.12.14, Windows). Современный браузер: Chrome, Edge, Firefox. Node.js, npm и сборка интерфейса не требуются.

После клонирования или распаковки архива откройте терминал в корне проекта:

```sh
python app.py
```

Откройте **http://127.0.0.1:8765**. На Windows также можно запустить `start.cmd`, если Python добавлен в PATH. На Linux/macOS при необходимости используйте `python3` вместо `python`. Остановка: Ctrl+C.

Приложение сразу анализирует приложенные обезличенные редакции 8 и 9 из `data/`. Основной сценарий воспроизводится без интернета, API-ключа или личного аккаунта. Автономный режим — алгоритмический анализ текста, а не скрытая LLM. Это явно показано в интерфейсе и отчёте.

### Дополнительная поддержка PDF

MD, TXT, DOCX, XLSX, CSV и TSV читаются стандартной библиотекой Python. Для текстовых PDF:

```sh
python -m venv .venv
# Windows PowerShell:
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
# Linux/macOS:
# .venv/bin/python -m pip install -r requirements.txt
# .venv/bin/python app.py
```

Проверенная зависимость: `pypdf==6.10.0`. Сканы, рисунки оргструктур, SmartArt и встроенные приложения не распознаются; нужен текстовый слой/OCR или текстовая копия. DOC/XLS сначала сохраните как DOCX/XLSX. Формулы Excel не пересчитываются.

## Проверка основного сценария

1. Откройте приложение. Дождитесь результата анализа реальных редакций.
2. В структуре найдите ДИТААД и ДОА: они появились в перечне §3.4 новой редакции. ДНМ и ДККМ сохранились.
3. Откройте «Карта функций». Найдите `5.4.4.а` и `5.4.4.б`: обязанности из старой редакции сопоставлены с `5.3.3.а/б` новой. Это перенос, а не потеря.
4. Откройте изменение обязательности §9.15: «осуществляется» заменено на «может осуществляться».
5. Проверьте кандидатов отсутствия: старые §§5.6.2, 5.6.3, 5.7.2. Отсутствие близкого текста требует проверки других документов, а не утверждения о фактической утрате.
6. Откройте замечание, прочитайте цитаты, подтвердите/отклоните его и добавьте комментарий.
7. На вкладке «Заключение» выгрузите HTML, JSON или таблицу CSV. Экспорт сохраняется также локально в `exports/`; путь виден в интерфейсе. Для PDF откройте HTML и используйте печать браузера.
8. В «Комплекты документов» выберите **контрольный синтетический пример**, загрузите и сравните. Ожидаются потеря отчёта о ликвидности, перенос реестра договоров, дублирование подготовки бюджета и потенциальный самоконтроль платежных операций.

Решения эксперта в интерфейсе хранятся до перезагрузки страницы. Сохраните заключение перед закрытием. Пользовательские экспорты исключены из Git.

## Автоматическая проверка и реальные результаты

```sh
python -B -m unittest discover -p "tests*.py" -v
python -B verify.py
```

`verify.py` запускает тесты и сохраняет протокол, фактические измерения, результаты анализа и самостоятельные HTML-заключения в `validation/`.

В текущем проверенном запуске **27 тестов прошли**. Реальные редакции: около **1,64 секунды**, 388 исходных функциональных фрагментов, 317 сохранённых, 32 изменённых, 36 перенесённых и 3 без близкого соответствия. Результат: 11 наблюдений (3 кандидата потери, 4 возможных пересечения, 1 потенциальный конфликт, 3 изменения). Значения относятся только к этому комплекту и запуску; это не оценка промышленной точности.

Проверки включают перенумерацию, изменение владельца, отрицания, обязательность, источники, контрольный кейс, Word/Excel/PDF, HTTP-сценарий, экспорт, отказ локальной модели и отбрасывание вымышленных ID/цитат модели. См. `validation/tests.txt` и `validation/summary.json`.

## Дополнительный режим языковой модели

Поддерживается локальный Ollama на **127.0.0.1:11434**. Сервис и модель должны быть заранее установлены пользователем. Лицензию выбранной модели следует проверить отдельно. Пример настройки для уже установленной модели:

```powershell
$env:ORGLENS_LLM_MODEL = "имя-вашей-установленной-модели"
python app.py
```

Linux/macOS:

```sh
ORGLENS_LLM_MODEL="имя-вашей-установленной-модели" python3 app.py
```

Включите дополнительную проверку в интерфейсе перед запуском. Модель рассматривает до восьми несопоставленных функций и до трёх кандидатов для каждой. Движок принимает только существующие ID и буквальные цитаты, сохраняет запретительный смысл и помечает соответствие как требующее проверки. Проверка цитат не доказывает правильность семантического вывода.

Если Ollama недоступна или ответ невалиден, анализ завершается автономно с предупреждением. В этой поставке живая модель **не запускалась**: её отсутствие и ошибки ответа проверены тестами с имитацией ответов. Не заявляйте на защите, что продемонстрирован запуск LLM, пока он фактически не выполнен.

## Параметры и архитектура

| Переменная | По умолчанию | Назначение |
|---|---|---|
| ORGLENS_PORT | 8765 | Порт локального интерфейса |
| ORGLENS_LLM_MODEL | не задана | Имя установленной модели Ollama |
| ORGLENS_OLLAMA_MODEL | не задана | Совместимый альтернативный параметр движка |

Адрес сервера ограничен 127.0.0.1. API-ключи не нужны. В базовом режиме документы не отправляются наружу. Дополнительная модель получает только отобранные фрагменты через локальный endpoint. HTTP-сервер предназначен для локального прототипа; промышленная аутентификация и многопользовательское хранение не реализованы.

- `app.py` — локальный HTTP API и раздача интерфейса.
- `backend.py` — извлечение, нормализация, сопоставление, правила риска, проверка доказательств, Ollama.
- `index.html`, `styles.css`, `app.js` — интерфейс без внешних ресурсов/CDN.
- `data/` — предоставленные обезличенные исходные редакции.
- `tests*.py`, `verify.py`, `validation/` — воспроизводимость.
- `docs/` — архитектура, соответствие критериям и сценарий защиты.

Подробнее: [архитектура](docs/ARCHITECTURE.md), [сценарий демо](docs/DEMO.md), [критерии](docs/CRITERIA.md), [сторонние компоненты](THIRD_PARTY.md).

## Границы применимости

Движок использует близость текста и предметные правила. Сильное перефразирование, сложные слияния/разделения подразделений и неявная ответственность могут требовать ручного уточнения. Сходство не является вероятностью. Один общий пункт может сопоставляться с несколькими функциями; эксперт обязан проверить полноту покрытия.

Предоставленные положения содержат ссылки на российские нормы. Агент не подменяет их законодательством Казахстана и не выносит юридическое заключение. Внешние нормативы, документы других операторов и полный комплект приложений не предоставлены — соответствующая проверка не заявляется.

Лимиты прототипа: до 30 документов с каждой стороны, до 15 МБ на файл, до 600 000 символов на документ, суммарно до 1800 пунктов. Файлы, которые не удалось прочитать, явно исключаются с предупреждением. Инструкции внутри документов рассматриваются как данные, не исполняются.
